# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read this first: the SDK version is pinned, and it is not the latest

This project is on **Expo SDK 54** (React Native 0.81.5, React 19.1, TypeScript 5.9).

**Do not upgrade the Expo SDK without checking the phone first.** The user's installed Expo Go supports **up to SDK 54**, and an SDK 57 build would not open on it at all. Their iPhone is on iOS 26.6.1, so this is *not* an OS limitation — it's the installed Expo Go version. The ceiling is therefore liftable: if they update Expo Go from the App Store, a newer SDK becomes possible. Until that is confirmed on the device, treat SDK 54 as fixed. A well-meaning `npx expo install --fix` or "upgrade to latest" will silently break the only way this app can be run.

The APIs here have also moved from what older training data suggests — `setNotificationHandler` takes `shouldShowBanner`/`shouldShowList` (not `shouldShowAlert`), triggers are typed via `SchedulableTriggerInputTypes`, routes live in `src/app/`, and the New Architecture is on.

**Check the versioned docs before writing Expo code from memory:** https://docs.expo.dev/versions/v54.0.0/

## What this is

A personal subscription tracker for one person's iPhone. Single user, no accounts, no login, no sync, no backend — all data lives on the device. The whole point is that it answers "what am I paying for, and what's about to charge me" without the user having to think about it, so **UX quality is the primary requirement**, not a nice-to-have.

## Environment: Windows, no Mac

Development happens entirely on Windows. There is no Mac and no Xcode — that is a hard constraint, not a preference, and it is why this is an Expo project rather than the SwiftUI app that used to live here (see commit `4825b43`).

- **During development** the app runs in **Expo Go** on the user's iPhone. `npm start`, scan the QR, changes appear in about a second.
- **For the finished app** a cloud build produces an `.ipa` that gets sideloaded via AltStore/Sideloadly.

**EAS cannot build this for free.** Its internal-distribution profile requires a paid Apple Developer account, because the ad hoc provisioning profile it needs can only be issued by one — an Apple restriction, not an Expo one. The free route is `.github/workflows/ios-unsigned-ipa.yml`, which compiles *unsigned* on a GitHub macOS runner and leaves signing to Sideloadly on the user's PC. `SIDELOADING.md` covers both routes.

## Commands

```sh
npm start                  # dev server + QR code for Expo Go
npm test                   # Jest over the pure layers
npm run web                # run in a browser
npx tsc --noEmit           # typecheck
npm run lint               # expo lint
npx expo export --platform ios --output-dir <tmp>   # prove the iOS bundle builds
npx expo install <pkg>     # ALWAYS use this, not `npm install`, for expo/native packages
node scripts/generate-brands.mjs   # regenerate the brand catalogue
```

`npx expo install` is not interchangeable with `npm install` — it pins versions compatible with the installed SDK. Using plain `npm install` for a native package will eventually produce a runtime mismatch in Expo Go.

**Typed routes**: `.expo/types/router.d.ts` is generated by the *dev server*, not by `expo export`. If `router.push('/some/route')` fails to typecheck after adding a route, run `npm start` once to regenerate it. A stale file also produces nonsense route names for files outside `src/app` — delete `.expo/` and restart if that happens.

## Verification — what can actually be tested here

This matters more than usual, because it is easy to write React Native that looks fine and is broken on device.

**Testable on Windows (do this before handing anything over):**
- `npm test` — Jest over `src/domain`, the pure parts of `src/data`, `src/ui/color`, and form/list logic in `src/features`
- `npx tsc --noEmit` and `npm run lint`
- `npx expo export --platform ios` — proves the iOS bundle actually builds

**Only testable on the user's phone:** how it *feels* (spacing, animation timing, gestures), notifications firing while the app is closed, haptics, real-device performance.

Never claim on-device behaviour has been verified from a Windows-side check. Say which of the two lists the evidence came from.

## Architecture

```
src/app/                      Expo Router routes only — thin, no logic
  (tabs)/index                Dashboard
  (tabs)/subscriptions        Full list
  (tabs)/insights             Charts and waste-spotting
  (tabs)/settings             Settings and backup
  subscription/[id]           Detail (pushed)
  add/, edit/[id]             Add & edit (modals)
src/domain/                   PURE TypeScript — no React, no react-native
  date, money, currency, cycle, fx, subscription, totals
src/data/                     Store, brand catalogue, rates, settings, migrations
src/ui/                       Tokens, colour maths, primitives, BrandIcon, charts
src/features/                 Screen-level components, grouped by feature
  dashboard, subscriptions, subscription-form, reminders, insights, settings
```

Routes under `src/app/` stay thin wrappers; the screen itself lives in `src/features/`.

### Rules that matter

- **Money is integer minor units** (`19.99` → `1999`), never floating point. Every conversion in and out goes through `src/domain/money.ts`.
- **`src/domain/` must never import React or `react-native`.** That purity is what makes it runnable under Jest on Windows — the only way the financial logic gets verified at all.
- **Dates are `YYYY-MM-DD` strings, never `Date` objects.** A billing date is a calendar date, not an instant; a `Date` shifts by a day when local midnight serialises as UTC.
- **Billing dates are computed as `anchor + n × interval` from the original anchor, never by stepping.** Stepping loses a 31st anchor permanently (Jan 31 → Feb 28 → Mar 28 instead of Mar 31). Documented and mutation-tested in `cycle.ts`.
- **Round once, at the end.** Cost normalisation returns *fractional* minor units; totals round after aggregating. Per-item rounding biases the headline figure.
- **`computeTotals` and `chargesBetween` answer different questions.** The first is an amortised average ("what does this cost per month"); the second counts real charges in a window ("what is actually leaving my account before month end"). A yearly plan contributes its whole price in one month and nothing in the others. Do not substitute one for the other.
- **Never silently drop an unconvertible subscription** from a total. Report it. A total that quietly omits one of the user's subscriptions is worse than no total.
- **Brand colours never tint UI surfaces directly.** They go through `toAccent()` in `src/ui/color.ts`, which pins lightness and saturation while preserving hue. Raw brand hex is only for the logo tile. Without this, near-black brands vanish and neon ones dominate.
- **The brand catalogue is generated**, not hand-written — `scripts/generate-brands.mjs`. It searches three simple-icons versions, because the current release has delisted many major brands (Amazon, Adobe, Xbox, OpenAI, Slack…) that older versions still carry. Never hand-write an SVG path: a wrong one renders as a plausible-looking blob.
- **Exchange rates must fail soft.** `src/data/rates.ts` rejects a malformed response *whole* rather than half-applying it, and any failure leaves the cached table in place. Stale rates beat a blank headline; a partially-wrong rate table silently corrupts every total.
- **Settings live in `src/data/settings.ts`, not `store.ts`.** The store imports AsyncStorage and expo-crypto and cannot run under Jest. Anything needing the shape of settings imports from the pure module.
- **iOS caps pending local notifications at 64**, silently dropping the rest. `src/features/reminders/plan.ts` sorts by fire date and truncates to 56. Reminder scheduling state is module-level and serialised, because the hook is mounted by more than one screen and two overlapping syncs can leave no reminders at all.
- **Charts are single-series on purpose.** Bar length carries magnitude, labels carry identity, colour encodes nothing. That avoids categorical-palette CVD problems and stops colour tracking rank. The chart hue was chosen by running the dataviz palette validator, not by eye. `palette.warning` and `palette.positive` sit ~7 ΔE apart under protanopia, so they are status-only and must always carry a text label.
- **Backups are the only recovery path.** A sideloaded app can lose its storage on a failed re-sign. `src/features/settings/backup.ts` refuses anything that is not recognisably one of our backups rather than wiping good data, and skips individual bad rows by name rather than discarding the file.

## Design

Direction B, "brand-forward": interface chrome is near-monochrome and all the colour comes from the subscriptions themselves. Dark-first; `palette` in `src/ui/theme.ts` is an object so a light theme would be a second palette rather than a rewrite. No component should contain a raw colour hex.

## Git workflow

The repository lives on the `main` branch. **Commit regularly and in small, self-contained steps** — the git history is the running record of what has been built.

- Commit as soon as a coherent unit is complete: a domain module, a screen, a bug fix, a refactor.
- Keep unrelated changes in separate commits.
- Short imperative subject line, then a body explaining *what* changed and *why* whenever the subject alone is not self-explanatory.
- Never write a message asserting that something works on device when it was only checked on Windows.

`.gitattributes` pins LF line endings. The generated `/ios` and `/android` folders are gitignored.
